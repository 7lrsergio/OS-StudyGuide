Goal/Assessment  
Goal 
Where are we going? What is expected? What will the student be able to do, know, and 
value at the end? 
The student will be able to design a solution to a synchronization problem. 
Assessment 
How do we measure? How will the student be assessed in the lessons and at the end of 
the module? Use general terms. Present this to the student at the beginning of the 
module. 
A student should be able to: 
• Identify a race condition 
• Describe priority inversion and priority inheritance 
• Identify the critical section of a problem 
• Match pseudo code to the appropriate synchronization hardware 
• Produce pseudo code using semaphores or a mutex lock to solve a given 
problem 
• Analyze a solution to a classic synchronization problem such as the bounded-
buffer, readers-writers, dining philosophers, and elevator problem. 
• Describe a monitor and condition variables 
• Differentiate between a semaphore and a monitor semaphore 
• Solve a synchronization problem using threads and semaphores 
Hook 
Pique the student’s interest using a case study, interesting story, experiment, or 
disaster. 
Question: Why do we have to synchronize some activities in a system? 
Lessons 
Divide the module into logical lessons (4-5 days). Create lessons, activities,

Representative Topics 
• Process interactions, process competition, concurrency, critical section (CS), 
interleaving, software solution to the CS problem, mutual exclusion, lockout, 
starvation, deadlock, process cooperation, producer-consumer problem with 
buffer of size 1, basic principles of semaphores, CS problem using semaphores, 
bounded-buffer problem, bounded-buffer problem with semaphores, 
implementation of semaphores, hardware support for synchronization, binary 
semaphores, busy-waiting, implementing P and V operations on general 
semaphores, examples of semaphores and problems with semaphores, priority 
inversion, priority inheritance, monitors, monitor, condition variables, c.wait(), 
c.signal(), monitor implementation of bounded-buffer problem, monitors with 
priority waits, implementation of a monitor, classic synchronization problems, 
readers-writers problem, monitor solution to the readers-writers problem, dining-
philosophers problem, approaches to preventing deadlock, monitor solution to 
DP problem, elevator algorithm, Java threads, Java synchronized method, Java 
semaphores 
Culminating Activity 
Tie it all together returning to the big idea. Go full circle. Create a culminating 
experience that ties lessons back to the module theme. Create module-level rubric and 
each topic is one of the lessons below.
