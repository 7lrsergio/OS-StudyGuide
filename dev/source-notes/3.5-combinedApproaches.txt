3.5 Combined approaches
An OS running only batch processes or only real-time processes could rely on only one of the suitable algorithms. Ex: SJF for a batch OS and EDF for a real-time OS. A general-purpose OS needs to handle different types of processes and thus a combination of different scheduling algorithms must be used.

A 2-tier approach
The simplest approach is to divide processes into two groups. Real-time processes run at the highest priority level but due to their short running times can use FIFO. Interactive and batch processes can be scheduled together using MLF.

Captions
Real-time processes are scheduled using ML. The shortest processes may use FIFO, longer processes time-share the CPU using RR.
Batch and interactive processes use MLF.
The shortest real-time processes enter at fixed priority levels in the ML scheme and use FIFO at each level. Processes r1 and r2 are processed before r3.
Longer real-time processes also enter at fixed priority levels but use RR at each level to distribute the CPU time evenly among the processes.
Batch and interactive processes always enter at level K-1 and, using MLF, gradually descend to lower levels based the total CPU time required.

In the 2-tier scheduling scheme the priority levels [1 : K-1] are used for interactive and batch processes, and the priority levels [K : N] are used for real-time processes.

Interactive or batch processes can execute only when no real-time processes are present.

A 2-tier approach with floating priorities
Most modern general-purpose OSs (Ex: Windows, Linux) use more sophisticated scheduling strategies to provide more flexibility. Real time processes use either FIFO or RR in an ML scheme. Interactive and batch processes use a variation of MLF. Every process is assigned a base priority at creation but an increment is added based on the past action the process has taken. Ex: Returning from a request for keyboard input would add 6 to the base priority while returning from a request for disk input would add only 1. Thus the current priority depends on the type of process and the process's behavior.

Captions
Real-time processes are scheduled using ML with fixed priorities between levels N and K. Within each queue, FIFO or RR is used.
Batch and interactive processes use MLF but the priorities fluctuate with the type of process and the action taken by each process.
Process p with the base priority 9 arrives.
If p returned from a request for disk input, an increment of 1 is added to the base priority and p enters with the current priority 9 + 1 = 10.
Another process q with the same base priority 9 arrives.
If q returned from a request for keyboard input, an increment of 6 is added to the base priority. Thus q enters the queue with the current priority 9 + 6 = 15.
