Goal/Assessment  
Goal 
Where are we going? What is expected? What will the student be able to do, know, and 
value at the end? 
The student will be able to describe the role of an operating system (OS), explain the 
OS structure, and describe the evolution and scope of OS’s. 
Assessment 
How do we measure? How will the student be assessed in the lessons and at the end of 
the module? Use general terms. Present this to the student at the beginning of the 
module. 
A student should be able to: 
• Describe the difference between abstraction and virtualization. 
• Determine the amount of time to complete computations for multiple processes 
with varying compute-bound and I/O-bound phases when using 
multiprogramming and/or time-sharing. 
• Describe the kernel, privileged instructions, kernel/user modes, and system calls. 
• Describe interrupts, traps, and interrupt handlers.  
• Describe Moore’s Law. 
• Identify advances in hardware technologies that caused changes in operating 
systems. 
• Identify different application environments. 
• Be able to describe the meaning of bits, bytes, words, kilobytes, etc., in the 
context of operating systems. 
• Compare and contrast SaaS, PaaS, and IaaS, in cloud computing. 
• Define open-source software and operating systems. 
Hook 
Pique the student’s interest using a case study, interesting story, experiment, or 
disaster. 
Question: What is the kernel of an operating system?

Lessons 
Divide the module into logical lessons (4-5 days). Create lessons, activities, 
experiments, homework and/or quizzes based on these grain size lessons. 
Lesson: The role of an operating system 
Lesson: The operating system structure 
Lesson: The evolution of scope of operating systems 
Lesson: Bits, bytes, words, kilobytes, etc. 
Lesson: Introduction to cloud computing 
Lesson: Open-source operating systems 
Representative Topics 
• abstraction, virtualization, multiprogramming, time-sharing (multitasking), CPU-
bound, I/O bound, timing, kernel, privileged instruction, kernal/user modes, GUI, 
shell, shell script, system call, supervisor (kernel) call, privileged/unprivileged 
instructions, interrupts, trap, interrupt handler, advances in hardware 
technologies, application environments, Moore's Law, mainframe, server, 
multiprocessor, distributed system, desktop/laptop, hand-held, real-time, sensor 
network, byte, word, kilobyte, megabyte, gigabyte, terabyte, etc., SaaS, PaaS, 
IaaS, open-source 
Culminating Activity 
Tie it all together returning to the big idea. Go full circle. Create a culminating 
experience that ties lessons back to the module theme. Create module-level rubric and 
each topic is one of the lessons below.
