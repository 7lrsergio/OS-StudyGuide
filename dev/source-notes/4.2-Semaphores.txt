4.2 Semaphores
The software solution to the CS problem has several major shortcomings:

The solution works only for 2 processes. When 3 or more processes need to share a CS, a different solution must be developed.
The solution is inefficient. While one process is in the CS, the other process must wait by repeatedly testing and setting the synchronization variables. The waiting process is only wasting CPU and memory resources without accomplishing any useful work.
The solution addresses only competition among processes. To address problems of process cooperation, entirely different solutions must be devised.
Basic principles of semaphores
Semaphores are general-purpose primitives that allow solving a variety of synchronization problems in a systematic manner.

A semaphore s is a non-negative integer variable that can be accessed using only two special operations, P and V.

V(s): increment s by 1
P(s): if s > 0, decrement s by 1, otherwise wait until s > 0
The implementation of P and V must guarantee that:
If several processes simultaneously invoke P(s) or V(s), the operations will occur sequentially in some arbitrary order.
If more than one process is waiting inside P(s) for s to become > 0 , one of the waiting processes is selected to complete the P(s) operation. The selection can be at random but a typical implementation maintains the blocked processes in a queue processed in FIFO order.

Captions
n concurrent processes need to access a CS. A semaphore mutex (named for mutual exclusion), is initially set to 1.
Before entering the CS, a process executes P(mutex), which sets mutex to 0. After leaving CS, the process increments mutex back to 1 using V(mutex).
If no other process is trying to enter CS then p1 can enter CS repeatedly. Thus lockout is not possible.
When multiple processes try to enter CS simultaneously, only one will pass P(mutex). All others block. Thus mutual exclusion is guaranteed and deadlock is not possible.
Upon exiting CS, the current process executes V(mutex). When mutex becomes 1, the waiting P(mutex) operations again compete with each other for entry into CS.
One of the blocked processes is chosen at random (p1) and enters the CS. pi may continue but starvation is not possible since pi cannot reenter CS before p1.
When p1 exits CS, the V(mutex) operation again enables one of the waiting processes, one of which is chosen at random to proceed into CS.

The bounded-buffer problem
The bounded-buffer problem is a classic synchronization problem intended to illustrate process cooperation. A producer process shares a buffer with a consumer process. The buffer has a fixed number of slots. The producer fills empty slots with data in increasing order. The consumers follows the producer by removing the data in the same order. The buffer is called a circular buffer because, upon reaching the last slot, each process continues with the first slot (modulo n).
The solution must guarantee the following:

Consumers do not overtake producers and access empty slots.
Producers do not overtake consumers and overwrite full slots.

Captions
Multiple producers and consumers share a bounded buffer of length N. Initially, all slots are empty. The index next_in shows the slot to be filled next and next_out shows the slot to be emptied next.
All slots are empty and thus only a producer can start by filling the first slot and advancing next_in to the next slot.
The producers can continue by filling more slots and advancing next_in each time.
As soon as the first slot is filled, the consumers can start emptying the slots in the same order and advancing the index next_out each time.
When a producer reaches the last slot, N-1, the index next_in is advanced by 1 modulo N, thus going back to slot 0.
The producers and the consumers can follow each other indefinitely around the buffer.
The solution must guarantee that, when the last slot is emptied (next_in = next_out), no consumer may proceed any further to avoid accessing empty or outdated slots.
Similarly, when consumers fall behind, producers must stop when all slots are full (next_in = next_out) to avoid overwriting data not yet consumed.

The bounded-buffer problem using semaphores
Semaphores offer a very intuitive and elegant solution to the bounded-buffer problem that satisfies the requirements that producers do not overtake consumers and vice versa.

Two semaphores are used to coordinate the processes. The semaphore f represents the number of full buffer slots and is incremented each time the producer places a new data item into the buffer and decremented each time the consumer removes an item from the buffer. The semaphore e represents the number of empty slots and is modified by the producer and consumer analogously.

Captions
A producer and a consumer share a buffer of size n. Initially, the semaphores e and f are set to show that all slots are empty.
Since no slot is full (f = 0 and e = n), the consumer becomes blocked on P(f).
The producer passes P(e), which decrements e to n-1.
After depositing a data item into the buffer, the producer executes V(f), which increments the number of full buffer slots to 1 and enables the consumer to proceed.
At this point either or both processes may continue. If the producer continues filling successive slots, e is decremented and f is incremented with each new data item.
The consumer may follow by decrementing f and incrementing e each time a buffer slot is emptied.
If the producer runs ahead and fills all slots, f = n and e = 0. The producer is now blocked from overrunning the consumer and overwriting slots not yet copied by the consumer.
Only after the consumer has emptied at least one slot and incremented e is the producer able to continue.
